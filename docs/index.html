Cli Griderator

Twenty terminals. One window. Nothing lost.

A grid of panes in a single window, each one a tmux session, so work survives a hide, a crash, or a quit. Built for people who run several long jobs at once, including the agent CLIs, and need to see which one is asking for an answer.

$ ./install · Linux, macOS, Windows

The window

Each pane shows what it is doing, which branch it is on, and where it is. A pane that blocks on a question marks itself and waits for you to come back.

What it does

Workspaces

Named pane sets for each way you work: agents, trade, write. Switching changes the panes and leaves every tmux session running, because only the clients detach.

Layouts and stacks

Choose the shape: 2x2, 3x2, master plus stack, a single column of six. Panes that belong together can share one cell as tabs, so twenty sessions never means twenty tiny terminals.

A control API

Send text into a pane, run a command, dump its output, wait for a pattern, or subscribe to an event stream. Scripts, cron jobs, and agents can drive the grid without knowing tmux.

Agent awareness

Idle, running, waiting, ended. The header counts the panes blocked on a question, one key goes to the next one, and a desktop notification fires only when a pane actually needs you.

Command palette

One keystroke opens a filter over every action, pane, workspace, theme and layout. Forty commands stop being trivia and start being discoverable.

Themes, keymap, honesty

A house palette plus eight stock themes, applied to the terminal and the chrome together. Remappable keys with a two-stroke prefix. Config is a plain JSON file you can read and diff.

Drive it from a shell

One line in, one line out, over a unix socket. The client is the same binary as the window.

# run a command in pane 3 and read what it printed
cligrid run 3 "make test"
cligrid wait 3 --until "passed|failed" --timeout 120
cligrid dump 3 --lines 20

# which panes want attention, and where are they
cligrid state --json

# react to the grid instead of polling it
cligrid events --kinds bell,exit,state

# a second grid beside the first, on its own socket
CLIGRID_SOCKET=/tmp/other.sock cligrid show

Linux, macOS, Windows

One source tree. Extract cligrid-<version>.tar.gz or cligrid-<version>.zip, then run the installer for this machine. VTE needs a POSIX pty, so Windows runs the Linux build under WSL 2 and WSLg shows it as a Windows window.

Linux

Native GTK3 + VTE + tmux. From the checkout or the archive:

./install

Or ./install.sh, the Debian package, or pipx install .

macOS

The same source. Homebrew supplies GTK3, VTE, pygobject3 and tmux, and the installer writes a Dock bundle.

./install

Needs Homebrew. Apple Silicon on Sonoma or newer downloads bottles; Intel Macs build gtk+3 from source.

Windows

WSL 2 and WSLg. There is no native Windows build: VTE has no Windows port.

powershell -ExecutionPolicy Bypass -File packaging\windows\install-windows.ps1

Then cligrid from any terminal. Optional: import the palette into Windows Terminal with griderator-wt-scheme.ps1.

# after any of the three installs
cligrid doctor               # check the machine before blaming the app
cligrid                      # start the grid
